Polymorphism is when a same piece of code works differently at different places that is with many forms.In object oriented programming paradigm, a method defined in Base class can be used with the same name in the various subclasses with different purposes.<\/p>\r\n

A common example where you would use is to calculate the length of different objects.For instance, the same built-in len() method is used to return the length of a string , length of a list or length of a dictionary, similarly the type() function works differently for different objects.<\/p>\r\n

Polymorphism can be among functions and objects or amongst class methods or in classes amongst inheritance.<\/p>\r\n

Polymorphism between functions and objects.<\/h3>\r\n

For instance, let’s create a common function driver for two classes and pass objects of different classes to it, but call the same methods for the objects.<\/p>\r\n\r\n\r\n\r\n
\r\n

class Manager:<\/p>\r\n

      def type(self):<\/p>\r\n

          print(“Full time Employee”)<\/p>\r\n
\r\n

     def bonus(self):<\/p>\r\n

           print(“Eligible for bonus”)<\/p>\r\n

 <\/p>\r\n

class Writer:<\/p>\r\n

     def type(self):<\/p>\r\n

           print(“Part Time Employee”)<\/p>\r\n
\r\n

     def bonus(self):<\/p>\r\n

           print(“Not eligible for bonus”)<\/p>\r\n
\r\n

def driver(obj):<\/p>\r\n

      obj.type()<\/p>\r\n

      obj.bonus()<\/p>\r\n
\r\n

obj_1 = Manager()<\/p>\r\n

obj_2 = Writer()<\/p>\r\n

driver(obj_1)<\/p>\r\n

driver(obj_2)<\/p>\r\n<\/td>\r\n<\/tr>\r\n<\/tbody>\r\n<\/table>\r\n

Polymorphism within Inheritance<\/h3>\r\n

In inheritance, polymorphism takes place between a base class and a derived or sub class.Methods with the same name can be used in base and derived class, and also overriding the function of the base class by redefining it in derived class is known as Method overriding.This is mostly done when when the child class is required to change a feature of parent class.<\/p>\r\n

Here is an example for deeper understanding<\/p>\r\n\r\n\r\n\r\n
\r\n

class FullTimeEmployee:<\/p>\r\n
\r\n

      def __init__(self, name, position, hours, salary):<\/p>\r\n

          self.name = name<\/p>\r\n

          self.position = position<\/p>\r\n

          self.hours = hours<\/p>\r\n

          self.salary = salary<\/p>\r\n
\r\n

      def bonus(self):<\/p>\r\n

          return (self.salary * 0.5)<\/p>\r\n
\r\n

class PartTimeEmployee(FullTimeEmployee):<\/p>\r\n

      def __init__(self, name, position, hours, salary):<\/p>\r\n

          super().__init__(name, position, hours, salary)<\/p>\r\n
\r\n

def inc_bonus(object):<\/p>\r\n

     x = object.bonus()<\/p>\r\n

     print(f'{object.name}\/’s bonus will be {x}’)<\/p>\r\n
\r\n

emp_1 = FullTimeEmployee(‘Atufa’, ‘Frontend Developer’, 6, 1000)<\/p>\r\n

emp_2 = PartTimeEmployee(‘Shireen’, ‘Content Writer’, 8, 2000)<\/p>\r\n
\r\n

print(inc_bonus(emp_1))<\/p>\r\n

print(inc_bonus(emp_2))<\/p>\r\n<\/td>\r\n<\/tr>\r\n<\/tbody>\r\n<\/table>\r\n

The super() charge and the subclassing will have the same bonus method, which calculates 50 percent bonus for either type of employee.<\/p>\r\n

\r\n

Atufa’s bonus will be 500.0<\/p>\r\n

Method Overriding<\/h3>\r\n

We don’t want to give a 50 percent bonus to a part time employee, thus we will use an overriding method to give a 10 percent bonus for a part time employee.<\/p>\r\n\r\n\r\n\r\n
\r\n

class FullTimeEmployee:<\/p>\r\n
\r\n

def __init__(self, name, position, hours, salary):<\/p>\r\n

    self.name = name<\/p>\r\n

    self.position = position<\/p>\r\n

    self.hours = hours<\/p>\r\n

    self.salary = salary<\/p>\r\n
\r\n

def bonus(self):<\/p>\r\n

    return self.salary * 0.5<\/p>\r\n
\r\n

class PartTimeEmployee(FullTimeEmployee):<\/p>\r\n

      def __init__(self, name, position, hours, salary):<\/p>\r\n

          super().__init__(name, position, hours, salary)<\/p>\r\n
\r\n

     def bonus(self):<\/p>\r\n

          return self.salary * 0.1<\/p>\r\n
\r\n

# common interface<\/p>\r\n

     def inc_bonus(object):<\/p>\r\n

         x = object.bonus()<\/p>\r\n

         print(f'{object.name}\\’s bonus will be {x}’)<\/p>\r\n
\r\n

# instantiating objects for the two classes<\/p>\r\n

emp_1 = FullTimeEmployee(‘Atufa’, ‘Frontend Developer’, 6, 1000)<\/p>\r\n

emp_2 = PartTimeEmployee(‘Shireen’, ‘Content Writer’, 8, 2000)<\/p>\r\n
\r\n

# passing the objects to common interface<\/p>\r\n

print(inc_bonus(emp_1))<\/p>\r\n

print(inc_bonus(emp_2))<\/p>\r\n<\/td>\r\n<\/tr>\r\n<\/tbody>\r\n<\/table>\r\n

Now the output with the same inputs will be<\/p>\r\n\r\n\r\n\r\n
\r\n

Atufa’s bonus will be 500.0<\/p>\r\n
\r\n

Shireen’s bonus will be 200.0<\/p>\r\n<\/td>\r\n<\/tr>\r\n<\/tbody>\r\n<\/table>\r\n

Run Time And Compile Time Polymorphism In Python<\/h3>\r\n

In the above examples, the interpreter chose the function which comes last i.e, in overriding and forgets about the previously defined method in case of calculating bonus.This is known as run time polymorphism.<\/p>\r\n

Python unlike many other famous programming languages such as java, c++ , go does not support compile time polymorphism because it doesn’t use function arguments for method signature.<\/p>\r\n
